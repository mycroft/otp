# otp

Store MFA secrets and generate TOTP/HOTP codes from the command line.

Secrets are kept either in a native database encrypted with a master password, or in
[pass(1)](https://www.passwordstore.org/). The project is a Cargo workspace:

- `crates/otp-core`: library (code generation, `otpauth://` URIs, storage backends,
  QR decoding), meant to be reused by a future UI.
- `crates/otp-cli`: the `otp` binary.

## Installation

```sh
cargo install --path crates/otp-cli                   # installs ~/.cargo/bin/otp
cargo install --path crates/otp-cli --root ~/.local   # or ~/.local/bin/otp
```

The interactive `otp tui` command is an optional feature:

```sh
cargo install --path crates/otp-cli --features tui
```

Run the same command again to update. To remove the binary, run
`cargo uninstall otp-cli` (the package is `otp-cli`, the binary is `otp`).

Optional runtime tools, looked up in `$PATH`: `pass` (for `--pass`), `grimshot` (for
`insert --qrcode`) and `wl-copy` (for `--clip`). The last two can be changed in the
configuration.

## Shell completion

Completion is generated by `otp` itself, so it covers subcommands, flags and entry
names. Folders along entry paths are offered too, so `Web/amazon.fr/pm@mkz.me` can be
completed one level at a time (`Web/`, `Web/amazon.fr/`). `otp insert` offers only
folders, since it creates a new name. Add the line for your shell:

```sh
# fish
echo 'COMPLETE=fish otp | source' > ~/.config/fish/completions/otp.fish
# bash
echo 'source <(COMPLETE=bash otp)' >> ~/.bashrc
# zsh
echo 'source <(COMPLETE=zsh otp)' >> ~/.zshrc
```

Completion never prompts. pass entry names come from the filesystem. Native entry names
are only offered when the master password is available without a prompt, through
`password_command` or `OTP_PASSWORD`; each completion then decrypts the database
(about 80ms, compared with about 2ms for pass names alone). With `backend = "pass"`
the database is never opened.

The completion interface is unstable in `clap_complete` (the dependency is pinned). The
lines above regenerate the shell code each time a shell starts, so it stays in sync
with the installed binary.

## Usage

```sh
# Without an exact entry name, otp lists entries (like pass)
otp                                         # list all entries
otp google.com                              # list entries starting with google.com

# Print a code (TOTP or HOTP)
otp google.com/codingmyc@gmail.com
otp -c google.com/codingmyc@gmail.com       # copy to the clipboard instead

# Export instead of generating a code (combines with -c; HOTP counters are untouched)
otp --secret google.com/codingmyc@gmail.com   # base32 secret
otp --otpauth google.com/codingmyc@gmail.com  # full otpauth:// URI
otp --qrcode google.com/codingmyc@gmail.com   # QR code, drawn in the terminal
otp --qrcode=google.png google.com/codingmyc@gmail.com  # QR code as a PNG

# Insert: paste an otpauth:// URI (hidden prompt, or read from stdin)
otp insert google.com/codingmyc@gmail.com

# Insert from a QR code: select a screen area with grimshot...
otp insert google.com/codingmyc@gmail.com --qrcode
# ...or decode an image file
otp insert google.com/codingmyc@gmail.com --qrcode=qr.png

# Insert a raw base32 secret (with optional --digits/--period/--algorithm/--counter)
otp insert google.com/codingmyc@gmail.com --secret

# Store in pass as google.com/codingmyc@gmail.com-otp
otp insert --pass google.com/codingmyc@gmail.com --qrcode

otp list [PREFIX] [--long]  # entries from both stores (or --pass / --native)
otp show NAME [--uri]       # parameters, or the otpauth:// URI (includes the secret)
otp rm NAME [--force]
otp mv FROM TO [--force]    # rename within its store; TO ending in / keeps the name
otp passwd                  # change the native database's master password
```

A name can only exist in one store. Lookups check pass first, since that doesn't need
the master password, then the native database. `--pass` / `--native` restrict any
command to one store; `backend = "pass"` or `backend = "database"` in the
configuration makes that the default.

## TUI

`otp tui` (built with `--features tui`) lists all entries, or only those in one store
with `--pass` / `--native`:

- Type to filter the list: case-insensitive substring match; Backspace edits, Ctrl-U
  clears.
- ↑/↓ select an entry. Its code, time left, issuer and account show
  in the right-hand column. pass entries are decrypted the first time they are
  selected.
- Enter copies the selected code with `clipboard_command` and quits. HOTP codes are
  only generated here, since generating one advances the counter. Esc or Ctrl-C quits.
- Tab or Ctrl-I opens the inspect window. It shows the current code, the base32 secret,
  every parameter and the `otpauth://` URI. There, `s` copies the secret and `u` copies
  the URI (then otp quits), `r` shows the QR code (Esc goes back), and Esc closes it.
- Ctrl-R shows the selected entry's QR code directly; Esc goes back to the list.
- Ctrl-N creates an entry. The name starts as the current filter; then choose `u` to
  paste an otpauth URI, `s` to type a base32 secret (TOTP with the defaults of `otp
  insert --secret`), or `q` to capture a QR code with `capture_command`. It goes to the
  store `otp insert` would use (`--pass`/`--native`, then `backend`, then native). Esc
  cancels at any step.
- Codes are shown as one unbroken string, so a mouse selection copies them as they are;
  set `group_digits = true` under `[tui]` in the configuration to show `123 456`.
- Ctrl-H hides or shows the code, and the secret in the inspect window (the countdown
  stays, and copying still gives the real values). It works in the inspect window too.
  To start hidden, run `otp tui --hidden` or set `hidden = true` under `[tui]`.
- Ctrl-?, Ctrl-/ or F1 shows the help with all shortcuts; Esc closes it.

Most terminals send Ctrl-I as Tab and Ctrl-? as Backspace. otp turns on the kitty
keyboard protocol where it's available (kitty, foot, WezTerm, Ghostty, recent Alacritty)
so they can be told apart. Elsewhere, use Tab and Ctrl-/ or F1.

The master password, if needed, is asked before the TUI starts, and never while it runs.
When the database was not opened at startup (e.g. with `--pass`), creating an entry
checks it for duplicates only if `password_command` or `OTP_PASSWORD` can open it. The
same applies to creating the database from the TUI. gpg runs without access to the
terminal, so use a graphical pinentry (or have gpg-agent unlocked) for pass entries;
errors are shown in the TUI.

## Storage

**Native database**: `~/.local/share/otp/otp.db` by default. A JSON envelope whose
payload is encrypted with XChaCha20-Poly1305. The key is derived from the master password
with Argon2id (64 MiB, 3 passes), and the header (format, KDF parameters, salt) is
authenticated. Entry names are encrypted too. Writes are atomic, and the file is mode
0600.

**pass**: entry `NAME` is stored as `NAME-otp`. The first line is the `otpauth://` URI,
so pass-otp and other tools can still read it. The lines after it hold JSON metadata:

```
otpauth://totp/Google:codingmyc@gmail.com?secret=...&issuer=Google&algorithm=SHA1&digits=6&period=30
{
  "created_at": "2026-09-25T18:54:47Z",
  "updated_at": "2026-09-25T18:54:47Z"
}
```

Existing pass-otp entries (`*-otp`, URI on the first line) work as they are. If one
has free-form notes after the URI, those lines are kept when otp rewrites the entry
(for example, to advance an HOTP counter).

## Configuration

`~/.config/otp/config.toml` (or `$OTP_CONFIG`). Every key is optional. A commented
sample is in [`contrib/config.toml.sample`](contrib/config.toml.sample).

```toml
backend = "pass"          # or "database"; default for --pass/--native (unset: both)
database = "~/.local/share/otp/otp.db"
# Get the master password from a command instead of prompting:
password_command = ["pass", "show", "otp/master"]
capture_command = ["grimshot", "save", "area", "{file}"]   # {file}: PNG to write
clipboard_command = ["wl-copy"]
qrcode_viewer_command = ["chafa", "{file}"]   # for otp --qrcode; unset: drawn by otp
password_store_dir = "~/.password-store"

[tui]
group_digits = false      # true: show codes as "123 456" instead of "123456"
hidden = false            # true: start with codes hidden (like Ctrl-H, or --hidden)
```

Environment variables:

- `OTP_DB`: overrides the database path.
- `PASSWORD_STORE_DIR`: selects the pass store, as it does for pass.
- `OTP_PASSWORD`: supplies the master password. It is meant for scripts and tests; it is
  visible to other processes of the same user.

## Development

```sh
cargo test --workspace --all-features   # pass test skipped without pass/gpg
cargo clippy --workspace --all-targets --all-features
```

GitHub Actions runs `cargo fmt --check`, `cargo clippy -D warnings` and the tests on
pushes to `main` and on pull requests (`.github/workflows/ci.yml`).

### Releasing

Set the new `version` in the root `Cargo.toml`, commit, then push a matching tag:

```sh
git tag v0.2.0 && git push origin v0.2.0
```

`.github/workflows/release.yml` runs CI and checks that the tag matches the crate
version. It then builds static binaries for `x86_64-unknown-linux-musl` and
`aarch64-unknown-linux-musl` and publishes them, with SHA-256 checksums, as a GitHub
release. Tags containing a `-` (e.g. `v0.2.0-rc.1`) become pre-releases.
